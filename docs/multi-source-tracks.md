# 다중 원본과 추천 트랙

## 동작

- 기록 선택은 최대 20개다. 생성 전 `선택한 전체 기록`을 선택하면 서로 다른 프로젝트의 기록도 유지한다. 특정 프로젝트만 선택하면 사용자가 명시적으로 범위를 좁힌다.
- CAREER와 LEARNING 모두 같은 원본 범위 규칙을 사용한다. 서로 다른 프로젝트의 성과는 합치지 않는다.
- 실제 모델 결과는 비어 있지 않은 원본마다 유효한 인용 또는 `excludedRecords`의 제외 이유가 있어야 통과한다. 제외 이유는 서버가 결과 Markdown에 붙여 승인 후에도 남긴다.
- 누락된 원본은 검증 실패로 처리하고 OpenAI/Gemini 모두 한 번 교정 요청한다. 총 75초 내 유효한 결과를 얻지 못하면 실패 응답한다. 인용 존재 검증은 문장별 사실 정확성까지 보장하지 않는다.
- 검토 화면에는 생성 대상과 인용이 연결된 기록 수를 구분해 표시한다. 기존 세션도 저장된 원본 범위로 표시하며, 예전에 좁힌 범위를 자동으로 확장하지 않는다.

## 추천 트랙

제목·본문·Notion 경로에 대한 서버 키워드 규칙(`keywords-v1`)으로 AI·RAG, 백엔드·API, 프론트엔드·UI, 데이터·DB, 인증·보안, 배포·인프라, 테스트·품질, 기획·협업을 추천한다. 근거 키워드가 없으면 미분류다. 한 기록은 여러 트랙에 속할 수 있다.

추천 트랙은 프로젝트 소속과 별개이며, 사용자 `project:` 태그를 바꾸지 않는다. 의미 기반 유사도 검색이나 사용자 수준 평가 기능은 아니다. 보관함과 생성 전 선택 화면에서 트랙별 기록 수와 필터를 제공하며 필터 변경 시 선택을 유지한다. 일괄 선택은 표시된 순서로 남은 한도까지 추가한다.

새 Notion 가져오기와 직접 입력·수정은 `track:` 및 `track-version:` 태그를 저장한다. 기존 기록도 조회 시 동일 규칙으로 `tracks`를 계산하므로 재업로드할 필요가 없다. 기존 데이터의 저장 태그를 일괄 갱신하지는 않는다. 추후 서버 검색은 이 차이를 고려해 별도 재분류 작업을 거쳐야 한다.

## 배포와 확인

에이전트·백엔드·프론트엔드를 함께 배포한다. DB 마이그레이션은 없다. 기존 입력 길이 제한은 유지한다. Gemini는 기록별 앞 1,200자, OpenAI는 최대 약 4,800자의 발췌를 전달하므로 긴 원본의 중간 내용이 모두 검토되는 것은 아니다.

| 사례 | 기대 결과 |
|---|---|
| 프로젝트 태그 없는 기록 3개 선택 | 전체 3개 또는 개별 프로젝트 선택지가 제공됨 |
| 전체 선택 후 커리어 생성 | 모든 원본에 인용 또는 명시적인 제외 이유가 있음. 다른 프로젝트 성과가 섞이지 않음 |
| 같은 자료로 학습 지도 생성 | 구체적 기록과 연결된 과제·산출물·확인 기준을 제안함 |
| 모델이 원본 하나를 누락 | 한 번 교정 요청. 계속 누락하면 422 응답 |
| RAG와 React 기록을 ZIP으로 가져오기 | 서로 다른 트랙으로 표시됨. 프로젝트 태그는 임의로 생성하지 않음 |
| 기존 업로드 기록 조회 | 재업로드 없이 추천 트랙 표시 |
| 두 트랙을 오가며 선택 | 기존 선택 유지, 중복 없이 최대 20개 |
| 검토 중 새로고침 | 생성 대상 수와 인용 근거 수 다시 표시 |

실제 모델의 글 품질과 브라우저·DB를 포함한 위 시나리오는 테스트 배포에서 별도 확인한다. 단위 테스트의 모델 응답은 대역을 사용한다.
